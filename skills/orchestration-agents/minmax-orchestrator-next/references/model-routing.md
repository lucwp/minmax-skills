# Model Routing

Allocate model capability to the narrowest node where marginal value exceeds marginal cost. Model names/pricing change; treat this as policy, not a current pricing source.

Principles:
- use the current/economical model for trivial, mechanical, or cheaply verified work;
- use a normal substantive model for bounded workers;
- use stronger reasoning only for genuinely complex narrow planning/reasoning nodes;
- before escalation, repair missing context, bad scope, wrong tool, and weak validation;
- escalate only the load-bearing node;
- reserve strongest judgment models for narrow high-consequence ambiguity.

Do not use premium capability for deterministic arithmetic, raw source collection, simple summarization, routine formatting, or prestige signaling.

If runtime does not expose model-specific controls, do not claim specific model routing occurred.
